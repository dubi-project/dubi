# VPS Root 确认探针

这是只读验收工具，不是 DUBI 用户命令。交叉编译后在已有 VPS 上运行，使用该节点 Store 中的身份和 TLS 配置；标准输入为 `{"status": <节点 status JSON>}`。不修改节点配置、成员、数据或证书。

每个样本先读取本地 applied index，再向输入视图中的 Root voter 请求 ReadIndex，最后等待本地应用达到非零确认位置。TLS 验证及 ClusterID / NodeID / RaftID 必须精确匹配；成功响应必须来自它声明的 Leader。

旧 Leader 可以返回零确认位置和新 Leader 提示。探针只跟随已验证身份返回的、输入视图中已知 voter 的提示；提示本身永远不算多数确认。一次样本最多访问每个已知 voter 一次，所有跳转和本地应用等待共享原来的 8 秒期限。未知身份、循环、超时、权限拒绝和无效证明均失败，不进行隐藏重试。新成员不在输入视图内时必须重新获取视图并启动新探针。

输出为逐行 JSON。`attempts` 保存每次请求的目标、Leader 提示、确认位置、耗时、结果及错误；`confirmed_index` 只在完整证明通过后赋值；样本须 `phase=passed` 且 `local_after >= confirmed_index > 0` 才能通过审计。重定向不等于故障，实际失败不能因后续恢复而从结果中删除。

支持最多 256 个计数样本，或最长 60 分钟的有限观察。持续模式最多每秒调度两次，工作者最多八个，验收通常使用两个。收到终止信号后停止调度，等待已接收样本完成并写出结果，避免漏掉收尾中的超时。`scripts/vps_root_observers.py` 使用该机制收集结果，最多等 12 秒；若未正常排空则记录收集失败。

收集目录和探针可执行文件由完整验收路径和 NodeID 的摘要隔离，不能仅使用 `candidate-holding-join` 等可能重复的目录名，也不能覆盖其他观察进程正在使用的程序文件。同一验收、同一身份仍采用排他创建，不覆盖旧证据；新验收或新身份使用独立目录。

开发机只交叉编译；测试二进制和在线探针在 VPS 运行。一次观察不能替代多数派、恢复流程、全量账本或持续流量验收。修正探针不能把旧的失败记录追认为通过。
