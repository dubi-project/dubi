# 节点故障、手动移除与自动再平衡

Dubi 对外不提供一套需要用户理解的“节点替换”流程。节点永久失效时，运维动作只有两步：管理员确认并手动移除旧节点；新机器按普通流程加入。新节点取得全新身份，底座随后自动修复数据、校验 Pack 并重新平衡。这里的“替换”只保留为内部安全协调语义，不是 CLI 资源、配置项或单独的运维命令。

超时、心跳丢失、一次 I/O 错误和临时卸载只能形成 `Unavailable` 等健康观察，不能自动移除节点，也不能自动缩小多数派分母。管理员移除前，系统必须保留旧身份的隔离/栅栏，防止旧机器恢复后以同一身份重新写入；新节点必须使用新的 NodeID、RaftID、StoreID 和 VolumeID。

当前实现**没有**自动判定永久失盘或退役 Node。`volume` 登记会让缺失目录、空挂载点、错误标记和介质替换失败关闭；同一原卷暂时恢复可以沿原身份继续使用。这个“健康观察恢复”不等于把已经授权标记 `Lost` 的旧节点重新接纳。三节点真实服务测试覆盖原卷被移走、原路径出现空目录时：该节点的 Pack 持有和新写入不被承认，另外两个真实持有仍可完成多数读取；原卷放回后，原身份才重新读到自己的字节。

对**仍在役且索引完整的同一 Node**，在线或停机登记健康新 Volume 后，后台记录修复可从当前已确认集合的认证来源重建失卷记录并同步切换本地位置；旧卷不必先恢复，在线登记不要求重启。这只修复已扫描的当前引用，不自动判定整卷已迁完、不安全移除旧卷，也不复制 Node 身份。

Root 身份隔离能力已实现，但它不是“替换任务”：仍承担 Root 或 Group 当前/待执行责任的身份不能被 `FenceNode` 直接处理。手动移除必须先走受控的 Root/Group 成员变更；成员真正移除后，旧 NodeID/RaftID 永不复用，旧机器恢复也只能被隔离。历史 Region cohort 不会永久阻塞已完成移除身份的 Fence。新机器通过普通加入生成全新身份，地址是否相同不影响身份判断。

永久损坏的节点不需要单独的用户态替换协议。手动移除必须由 Root/所属 Group 以持久成员变更完成，不能只删 Root 目录中的节点记录；移除前仍要检查当前控制面多数和数据安全门槛。对确认的单节点 Region，底座会在同一次明确的 `node remove` 中先记录 Region Group 退休，再完成 Root 注销和身份 Fence；这不是用户需要理解的 rebuild 流程。移除完成后，新节点走普通 `join`，然后复用正常的 Region 增长、Repair 和 Pack 校验流程自动补齐。直接把旧节点从 Group 或 cohort 删掉而不经过成员变更，仍可能缩小数据多数分母，必须拒绝。

如果整个 Region 都不可恢复，普通运维动作仍然只有逐个执行 `node remove`，然后让新机器按普通 `join` 加入同一个 Region 名称。`node remove` 从任意存活 Node 进入 Root 控制面；如果目标 Region Group 已经没有 quorum，Root 会在这次明确的删除请求中记录该 Group 已退出，再完成 Node 注销和身份栅栏，不等待故障 Group 响应。底层会在最后一个旧成员移除后自动建立新的内部代际，并让新节点从其它可用 Region 补齐数据；这个代际不是用户命令、配置项或替换流程。旧 NodeID/RaftID 永不复用。若原节点后来被救回，则沿原身份追数据，不进入新代际。

操作顺序与门禁：

1. 健康巡检只把失联节点标记为 `Unavailable`，不自动改变成员。节点恢复时保留原身份，自动追赶落后数据；若仍无法达到多数，区域或集群保持 `Degraded`。
2. 经授权的操作者确认节点永久失效后，提交普通节点移除请求。Root/Group 必须以受控成员变更完成，不能只删除目录记录，也不能用移除来绕过数据多数检查。
3. 新机器通过普通加入获得全新 NodeID、RaftID、StoreID 和 VolumeID。新节点的空 Pack 不计作已有数据持有；加入后由正常 Region 增长和 Repair 自动补齐、校验并重新平衡。接纳入口必须由仍可用的集群级 enrollment authority 提供，不能把已移除 bootstrap Node 作为唯一签发点。
4. 数据多数恢复且没有未解决欠账后，区域或集群健康状态自动回到 `Normal`。任何阶段不确定时按旧代际失败关闭。

当前成员的后台 Repair 已把分页游标、当前 Region generation、Group epoch、Fence index、节点集合和未解决欠账保存到节点本地 `<store>/dubi-repair-state`；重启只在 Root 集合完全匹配时续扫，代际变化会从头重扫。`Node Snapshot` 可以加速新节点预热，但不能复制旧 Node/Raft 身份，也不能替代最终 Pack 与权威引用的复验。这里没有额外的替换任务、覆盖报告或替换状态机。
