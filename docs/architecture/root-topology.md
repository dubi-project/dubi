# 自动 Root 控制面拓扑

Root 的 voter 是控制面共识角色，不是数据副本数。额外节点作为 Root learner 保持目录追赶，仍可参与独立的数据 Group 和 Placement。此实现不提供数据的 LocalReady/GeoReady 证明，不代表 P06 已全部完成。

## 默认策略

正式托管 `server` / `join` 流程自动执行，不新增配置或专家开关。目标只取 Root 已持久接纳的成员及其固定 Region 登记，不从存活节点列表、Volume 数或可用空间重新计算分母。历史 Node 描述符但已不在 ConfState 的节点不参与，控制器不会自动重新加入已移除节点。

| 持久 Region 数 | Root 目标 |
| --- | --- |
| 1 | 节点数为 1/2 时保留对应数量；至少 3 个时采用不超过节点数的最大奇数集合。 |
| 2 | 跨两区轮流选取、尽量均衡，采用上述数量规则。不能声称任意一个区域失效后另一侧都可写。 |
| 至少 3 | 每个 Region 一个 voter，其余成员为 learner。 |

内部最多 31 个 Root voter；一个或两个区域有更多节点时，多余节点保持 learner。超过 31 个 Region 明确报告不支持，不悄悄省略区域。该限制不是用户设置的副本数，后续扩展需要协议和资格验证。

区域内优先保留现有 voter，然后按系统生成的 RaftID 排序；区域名排序只保证确定性。新加入的较小随机 ID 不会单独引起投票成员抖动。登记的 Region 必须对应实际部署故障域，名字本身不能证明物理隔离。

## 执行和持久边界

1. 仅当前 Root leader 调度，先完成 Root ReadIndex，再读取成员和 Node 描述符的同一 applied cut。
2. 当前为 joint 配置时不发起第二个计划，让 Raft 自动完成退出 joint。否则从上述持久拓扑推导目标，不用健康过滤目标。
3. 本地 leader 若应成为 learner，先向一个目标中的既有 voter 转移领导权，下一轮由新 leader 重新计算。
4. 提案前在 Group 锁内重新验证 leader、磁盘准入、完整 ConfState CAS，并检查旧/新 voter 全部近期活跃且 Match 已达到当前 Commit。滞后/不活跃时等待下一轮，不缩小计划。
5. 一个角色变更提案采用 Raft 自动 joint consensus：旧/新多数共同确认后自动退出。多名 learner 同次晋升，不需要先形成稳定的两 voter 中间配置。多余 voter 降为 learner，而不是删除 Node 或数据。

Raft 持久 joint ConfState 和日志就是正在执行的角色变更记录；控制器不持有能绕过恢复的易失进度。重启先恢复日志/状态机，再继续 joint 自动退出及后续规划。提案返回成功不等于完成，下一轮检查真实应用的 ConfState。CAS 过期、追赶未完成是可重试状态；存储、目录和超限错误保留并报告。

Root admission 与拓扑协调在同一个后台串行通道执行，数据 Group 协调独立运行。并发 Join RPC 仍由实际 ConfState CAS 保护。所有后台工作随 Server 取消并等待退出，之后才释放 Host/Store。上下文不能强制中断任意文件系统调用。

## 能力边界

- 单节点无控制面冗余；两 voter 必须两者在线，不能容忍一台失效。自动形成三 voter 后才具备正常单 voter 失效容忍。
- 三个区域各一 voter 可以在一个区域丢失后由另外两个形成 Root 多数。但如果多个区域恰好同时丢失各自唯一的 Root voter，即使很多 learner 仍在线，也不能绕过丢失的 Root 多数直接晋升它们。
- 一般性的“多数 Node 在线且多数 Region 在线，所以所有请求必定可用”并不由单个平面 Raft Group 保证。Root、数据 Owner Group、实际有效拷贝和当前确认级别必须分别检查。
- 本控制器不做失联替补、强制移除、维护授权、受控地址/Region 变更或灾难恢复。故障期间不会为了收敛目标而跳过旧 voter 活跃/追赶检查。
- 额外节点持有 Root 日志并不代表持有任何业务数据。[区域集合目录、自动初始 Group 与第一代栅栏全员确认](region-cohorts.md)已独立接通；后续自动扩展交接、Placement/Repair、卷均衡与业务数据多数耐久确认仍需落地。

## 验证

规划测试覆盖单区域 1–5 节点、双区域、3×3、3×5、四区域、既有 voter 保留、输入顺序不变性及超限/不完整/joint 视图拒绝。Raft 实测覆盖从一 voter 同次扩成三 voter、joint 中途重启、自动退出、降为 learner、旧配置 CAS、离线新/旧 voter 拒绝、原日志不变、leader 转移前置要求及磁盘压力拒绝。

正式 CLI 构造、自动身份/凭证加入和真实 TCP/mTLS 集成测试覆盖单区域三节点、三区各一节点与 3×3 九节点的自动投票集合收敛、Leader 停机后的选举和 Root 写入、原节点回归追赶、全群停机后无新身份/凭证的冷启动。凭证管理遇到领导权转移的 Unavailable/DeadlineExceeded 时复用同一个 draft 重试，不创建另一份凭证。

九节点测试先暴露首次 Enroll 缺少临时错误重试，另用真实 mTLS 的一次 Root 不可用回归复现。正式 Enroll 已复用原 CSR/凭证、最多八次有界 RPC、指数退避且总窗口不超过 30 秒；权限、参数、前提条件和资源压力不重试。重试不能把未确认结果变成成功，也不自动换身份/私钥/CA。

完整门禁随后捕获 Root 接纳阶段遇到联合变更时一次尝试即退出的问题。Join 客户端同样按原回执有界重试临时不可用/超时，每端点最多八次、所有端点合计最多十六次 RPC、总计三十秒，已知其他路由优先。mTLS 回归覆盖确认前失败、确认后响应丢失、次数上限、取消和权限/压力不重试；重复调用返回同一个持久接纳位置。

测试全部在同一主机的临时目录运行，不代替真实区域、独立磁盘、WAN、长时间运行或物理掉电资格。生产结论仍为 No-Go。
