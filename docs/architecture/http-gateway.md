# 内置 HTTP Gateway 与 Web UI

状态：公共 HTTPS、托管证书续期、管理会话与权限隔离已可运行。React 控制台已编译内嵌，接入集群、区域、节点、Volume、Tenant、凭证、Repository、备份和监控诊断接口。具体读写范围见 [管理 API](../api/management.md)、[租户 API](../api/tenants.md)、[访问与备份 API](../api/access-backup.md)、[监控与诊断 API](../api/monitoring.md)。Config 业务接口已接入真实 Runtime，Go SDK 尚未实现。开发前同时阅读 [四层架构](four-layer-architecture.md)、[开发规范](../development/engine-module-gateway.md) 和相关源码。

## 1. 定位与职责

HTTP Gateway 是 Dubi 内置 Gateway，运行在同一个 `dubi server` 进程内，统一承载：

- 管理 API：集群、区域、节点、Volume、Tenant、Repository、备份恢复及维护任务。
- 业务 API：由各 Module 定义的受约束公开操作。
- 监控入口：存活、就绪、指标采集以及经过授权的状态与诊断数据。
- Web UI：内嵌的管理控制台，方便管理员通过浏览器管理和维护集群。

API 是对外契约，Web UI 是 API 的客户端，都不构成第五层服务端架构。无需额外部署前端服务器、Node.js、Nginx 或独立管理后端。

```text
浏览器 Web UI / SDK / HTTP 客户端
                ↓
        内置 HTTP Gateway
                ├─ 业务 API → Module → Engine → Runtime
                ├─ 管理 API → Runtime 管理服务接口
                ├─ 监控入口 → 只读状态与指标接口
                └─ 静态资源 → 内嵌 Web UI
```

管理 API 不需要虚构一个业务 Module 来包装节点或备份操作。它调用 Runtime 的受控管理服务，复用现有校验、成员变更、授权和持久任务机制；不能直接修改 Root 状态、Pack 或底层数据库。CLI 与 HTTP 应复用这些服务，不通过执行 CLI、解析终端输出来实现 Web API。

HTTP Gateway 负责协议、身份校验、授权上下文、请求限制和错误映射。业务语义由 Module 定义，集群操作由 Runtime 定义。静态 UI、探针和管理查询都不能成为绕过这些边界的入口。

### 1.1 四类访问共用一个入口

| 使用方 | 请求 | 身份与范围 |
| --- | --- | --- |
| 浏览器打开控制台 | HTML、脚本、样式及登录入口 | 静态登录页面可匿名，不包含集群私密信息 |
| Web UI 调用 API | 管理 API 与 Module 业务 API | 浏览器登录会话；分别检查管理权限与 Tenant 数据权限 |
| SDK / 应用 | 同一套公开 API | Token；业务凭据不能因使用 SDK 获得管理权限 |
| 监控程序 | `/healthz`、`/readyz`、`/metrics` | 最小探针可匿名；详细指标使用独立的监控访问权限 |

内嵌 UI 只表示静态资源随服务端发布，页面代码仍在浏览器执行，API 请求仍经过公共网络入口。UI 与 API 同源，共用该入口的服务端证书。SDK 和监控客户端不需要 Node 私钥或 Node 客户端证书。

HTTPS 负责连接加密与服务端身份验证；登录、Token 和授权负责操作权限。证书可信不代表调用者已获授权，Token 有效也不允许跳过服务端证书验证。公共入口与内部节点通信分别管理证书，不新增四套客户端专用服务。

## 3. URL 与 API 契约

以下为目标命名，新增接口按实际功能逐个交付，不一次性实现全部路由：

| 路径 | 用途 |
| --- | --- |
| `/`、`/assets/...` | 控制台页面和静态资源 |
| `/api/v1/me` | 当前已验证身份及其允许的操作范围 |
| `/api/v1/admin/...` | 集群管理、状态与诊断 |
| `/api/v1/config/...` 等 | 对应 Module 的业务 API |
| `/healthz` | 当前节点存活检查 |
| `/readyz` | 当前节点明确约定的就绪检查 |
| `/metrics` | 当前节点的 Prometheus 采集接口 |

`/v1/me` 保留原 Tenant 身份响应；`/api/v1/me` 同时支持 Tenant 身份和管理/监控身份，但不混合权限。API 路径不能被前端页面回退规则吞掉：不存在的 API 返回 API 错误，不返回 HTML。

公开契约包含参数、响应、权限、错误码、分页和限制，源文件归入 `api/v1/`；可以用 OpenAPI 描述 HTTP 契约，但不为了第一版先建立大型生成框架。不得把内部 Go/Raft 类型原样导出成公开契约。

统一要求：

- 列表分页有上限，查询与请求体有预算；大对象采用已有受控数据通道，不能无限读入内存。
- 使用稳定错误码区分参数错误、未认证、无权限、不存在、冲突、资源不足、不可用和结果不明，不能全部变成 500。
- 请求关联 ID 用于诊断；写入重试使用稳定 RequestID。关联 ID 不自动等于幂等键。
- 超时或断线不等于没有执行。结果不明时返回可查询或安全重试的线索，同一请求不得换 ID 盲目重放。
- 接受异步任务返回任务标识，只代表已经受理，不代表操作完成。复用现有持久任务机制，不创建 UI 专用的第二套任务系统。
- 响应包含必要的版本和观测时间；多节点汇总标记缺失、过期与部分结果，不伪装成一个原子快照。
- 如涉及本区域确认和 Geo 完成，按实际语义分别呈现。Gateway 不调整底座确认策略。

### 3.1 Go SDK 接入

Go SDK 规划为独立的 `dubi-go` 仓库，第一版通过 HTTP Gateway 调用公开 API，不新增 SDK 专用协议或服务端入口，不导入服务端 `internal/` 包，不直接连接 Engine、Raft 或内部 RPC。本文确定的是接入规划，不表示 SDK 已实现。

SDK 与 Web UI 的业务数据页面共用 Module 的公开契约、权限和错误语义。SDK 是客户端形式：Config、Files、Search 等接口属于业务 API；可选的 `Admin` 接口调用管理 API，并要求对应管理权限。不能因为使用 SDK 就扩大凭据的权限。

SDK 提供连接地址、TLS、凭据、超时、`context.Context` 取消、类型化错误、分页和有界重试。它可以连接任意健康节点，由 Runtime 路由到实际执行位置；不实现 Owner 查找或第二套集群路由。重试和切换入口必须保留端到端期限及写入 RequestID，仅在契约允许时重试；结果不明不能转换为未执行，也不能更换 RequestID 重新写入。

SDK 按已交付的 Module 增加接口，不提前生成不可用的方法。首个闭环可与 Config HTTP API 一起交付；验收需真实服务端联调，覆盖身份撤销、版本冲突、分页、取消、响应丢失和安全重试。契约变更同时考虑 SDK 与 UI，版本兼容范围和不支持的操作必须明确。

### 3.2 全局业务数据管理

Web UI 支持从一个入口选择 Tenant 和 Module，浏览或管理整个集群的业务数据，不要求先选择持有数据的节点。全局入口不等于绕过隔离，也不要求第一版支持跨 Tenant 联合查询。

集群管理权限与业务数据权限分开判断：管理节点、容量或备份的权限不自动授予读取 Tenant 内容的权限。可以显式授予管理员全局数据权限；没有该权限的身份只能访问被授权的 Tenant 和操作范围。

对于普通 Tenant Token，目标 Tenant 始终由已验证凭据绑定。对于具有明确跨 Tenant 数据权限的管理员，目标 Tenant 可由界面选择，但必须由服务端校验其授权范围，再构造可信的 Tenant 上下文传入同一 Module API。客户端提交的 TenantID 本身不是授权证明，不能用这条管理路径绕过 Tenant 检查。

界面持续显示当前 Tenant，切换时隔离缓存、选择项和待提交操作；敏感写操作明确目标，审计记录实际操作者、目标 Tenant、操作和结果，不把管理员伪装成租户身份。全局数据授权机制尚需实现，在完成前不能开放跨 Tenant 数据访问。

每个 Module 按实际需求提供列表、分页、查询和修改接口，供 SDK 与 UI 复用。全局管理不开放任意内部命令、裸 Keyspace 或底层存储读写；没有 Module 公开接口的数据不能靠 UI 绕行访问。

内部寻址遵守 [数据寻址与隔离](data-addressing.md)：同 Tenant 不同 Module 的数据独立，即使复用同一 Engine。API 路由固定 Module，Module 的服务端依赖固定 Engine；客户端参数、Header 和请求体不能覆盖这些身份。SDK 和 UI 不提供 Dataset 创建、Keyspace 或 Range 选择接口；列表和查询只暴露对应 Module 的业务概念。

## 4. 身份、权限与监听边界

统一 HTTP Gateway 不等于统一权限。必须区分集群管理员、Tenant 应用、浏览器会话和监控访问范围。

- Tenant 来源于服务端验证的凭据，不能由路径、Header 或请求体任意选择。Tenant Token 不能执行集群管理操作。
- 管理 API 需要明确的管理身份和操作授权。不能仅因为同源、来自本机或拥有某个 Tenant Token 就获得管理权限。
- 首版通过 Node 认证的 `dubi access create --role admin` 建立管理员凭据；首次使用该高熵 Token 登录后，在“访问与凭证 / 管理账号”创建账号；日常默认使用账号密码登录。两种方式均换取最长 12 小时的会话。退出撤销会话；撤销父 Token 会使其全部会话失效。需要恢复访问时，通过本机 Node 身份签发新凭据并撤销旧凭据。不提供固定默认密码、公开注册或外部身份服务依赖。忘记账号密码时，可通过 Node 身份签发临时 admin Token，登录后重置账号密码，再撤销临时 Token。
- 不把节点私钥发给浏览器，不通过降低内部 mTLS 要求来实现网页登录。公开 HTTP listener 不注册内部 Root/Group/节点 RPC。
- Web UI 默认同源调用 API，不使用宽泛跨域放行。若使用 Cookie 会话，需具备 Secure、HttpOnly、SameSite、CSRF 防护及服务端注销/过期语义。身份凭据不进入 URL、静态文件或日志。
- 最小存活/就绪探针免登录；`/metrics` 需要 monitor/admin Token 或有效管理员会话。monitor 不能访问管理 API，Tenant Token 不能读取指标。授权依赖 Root 确认，不可确认时返回 503；探针不依赖该授权查询。
- 无法确认授权时拒绝敏感操作；独立的轻量本地存活探针不应为证明进程存活而等待全局共识。

目标保持一个简单的对外 HTTP 入口，不要求管理员逐节点配置一堆 ID、名称或必填 YAML。入口参数在首次配置后保存到节点元数据目录的 `gateway.json`，不要求手写配置文件。内嵌 UI 不代表自动绑定公网或自动开放管理权限。远程浏览器使用还需要正确的服务端证书信任，不要求用户关闭 TLS 校验。

### 4.1 公共入口与证书生命周期

目标是一次配置、重启复用，不要求每次启动重复传入公共监听地址、访问地址或证书选项。节点本地绑定地址与对外访问地址分别保存和校验；证书需要覆盖客户端实际使用的域名或 IP，不能因为支持任意节点路由，就假定一张证书适用于所有节点地址。

公共 HTTPS 提供两种明确的部署方式：

- 托管证书：在所选签发机构支持目标地址且验证条件满足时，自动申请、提前续期、保存并加载；失败有界重试，报告原因与剩余有效期。部署时只要求必要的访问地址和所有权验证信息，不承诺任意内网地址或不可达 IP 都能获得公共可信证书。
- 外部证书：接入部署方提供的证书链和私钥，校验地址、有效期与密钥匹配，监测并加载更新；明确由部署方续期，不把文件热加载描述为自动续期。

内部 Node PKI 继续由节点机制管理，不用公共 CA 替代节点身份，也不为了 HTTPS 新建通用 Secret Store。公共证书管理属于进程入口能力，不依赖 Config Module；本地证书和签发凭据需受保护保存，不进入静态资源、日志、公开响应或普通集群配置明文。

托管续期由服务进程的维护机制完成，不依赖管理员另配 cron 或本对话的定时任务。并发签发需按证书目标协调，节点重启或切换不能让所有节点重复申请同一目标；首版每个节点配置自己的可验证域名或 IP，本地续期文件锁和验证 listener 防止同一部署目录并发签发。共享域名跨节点签发协调尚未提供，不能把同一域名的托管配置复制到所有节点；不提供 DNS 厂商插件。

候选证书验证通过后再切换。续期失败时继续使用仍有效的当前证书，不能把错误候选覆盖上去；到期后不降级为明文或跳过校验。剩余有效期、最近成功时间、重试状态与失败原因应进入 CLI、管理状态和监控，HTTPS 已过期时仍可通过本机管理入口诊断。必须区分节点时钟错误、网络不可达、验证失败和签发限制，不能只显示笼统的“服务异常”。

首版已实现：公共配置持久化、外部证书候选校验与有效缓存、ACME HTTP-01 签发、剩余三分之一有效期提前续期、每小时检查、失败按一分钟至一小时退避、原子保存和新握手切换。托管状态写入节点本地文件，`dubi gateway status` 可在 HTTPS 不可用时读取最后一次观察；不据此认定进程在线。证书到期时间、更新失败和下次检查时间加入受保护的 `/metrics`。

签发需公网 TCP 80 可达，服务账号需有绑定验证端口的权限；验证 listener 只在签发/续期期间提供 HTTP-01 路径，不提供明文管理 API。默认使用 Let's Encrypt；IP 申请使用其 shortlived profile。`--api-acme` 表示采用托管签发并接受所选 CA 的服务条款，`--acme-directory` 可用于测试 CA。ACME 实现使用 [Go 官方 ACME 客户端](https://pkg.go.dev/golang.org/x/crypto/acme)。

## 5. 任意节点访问

客户端可以连接任意健康节点的 HTTP Gateway，由 Runtime 完成必要的路由与内部转发；不要求客户端寻找 Root Leader、Owner 或某个管理主节点。

这不表示每个节点持有全部数据，也不表示失去必要共识、数据确认或授权条件后仍能执行写入。Gateway 必须保留 Runtime 的不可用、冲突和结果不明语义。

管理操作同样通过 Runtime 路由到适当执行位置。节点本地属性必须明确目标 NodeID，例如 Volume 路径和 File Repository 目录，不能误用“当前接收 HTTP 请求的节点”代替用户选择的目标。

探针和指标默认是访问节点的本地观察；集群汇总由管理查询服务在有界并发、超时和缓存预算下完成。指标抓取与页面刷新不修改业务或拓扑状态，不应无限全群扇出或执行昂贵全盘扫描。授权确认复用 Root ReadIndex，其实现可能提交控制屏障；不能把授权查询描述成完全不经过共识。

## 6. Web UI 范围与托管

控制台源码位于独立仓库 `dubi-project/webui`（工作区与 `dubi` 并列），框架确定为 React + TypeScript + Vite。已确认蓝灰色管理界面，参考 Stitch 的信息组织，现已接入登录、退出、会话恢复、集群概览、区域与节点、存储与容量、维护诊断和入口信息。`internal/gateway/httpapi/console/` 只保存生成的静态资源与校验清单，不手工修改。`scripts/build.sh` 按锁文件构建前端、同步产物并编译 Go；Go `embed` 将文件装入 `dubi` 二进制。运行时没有 Node.js、Nginx 或独立前端服务依赖。

静态资源使用内容哈希和适当缓存；入口 HTML 避免长期缓存旧版本，敏感 API 响应不得按静态资源缓存。前端路由回退只处理页面请求。构建、打包和启动检查应发现缺失资源，不能发布一个空白控制台却报告 UI 可用。

第一阶段页面：

1. 集群概览：整体状态、区域/节点数量、容量、数据保护与待处理问题。
2. 节点与 Volume：状态、资源、故障、Repair/Rebalance 进展。
3. 监控与诊断：实时观测、异常原因、影响范围、采集入口及更新时间。

随后接入已验证的管理 API：Tenant 凭据、Repository、备份恢复、节点命名/移除、Volume 管理。模块页面从 Config 开始，按实际能力提供，不给每个 Engine 强制建立用户界面。

页面必须遵守底座设计：不引入 Project、Node Snapshot、Node Replacement、Region Rebuild，不要求用户配置副本数，不按 Engine 拆 Volume。超时只展示不可用，不自动删除节点；危险操作展示服务端预检、对象与影响后再确认，后端仍需重新校验，不能信任浏览器预检结果。

状态展示约定：

- 正常、降级、不可用、未知分别表达，未知不是零，也不是正常。
- 没有真实数据时展示暂无数据或未启用，设计稿样例不得进入正式响应。
- 修复、迁移、备份等任务有阶段与最近进展；没有可靠分母时不捏造百分比或剩余时间。
- 浏览器断开不取消已持久受理的管理任务，重新访问可查询；普通读请求则随客户端取消而释放资源。
- UI 使用有界轮询和退避，后台页面降低刷新频率，不把长期连接或推送系统作为首版前提。
- 历史趋势和通知只在有真实数据源时提供。首版不强制 Prometheus/Grafana，也不为展示图表新造一个无限保留的指标库；外部监控可以选择接入。

## 7. 代码组织与协作

目标职责：

```text
api/v1/                    HTTP 契约、错误码和版本约定
internal/gateway/http/     路由、中间件、管理/模块适配、静态资源托管
internal/server/           进程装配、TLS、listener 与生命周期
internal/platform/        管理服务、身份、监控和 Runtime 能力
internal/module/          协议无关的业务 API
../webui/                 独立 React 控制台仓库与前端构建配置
```

这些是职责规划，不表示目录和适配器都已存在。现有 `public.go`、`metrics.go` 可以逐步迁入清晰的 Gateway 适配层，先保持行为与测试，不为了目录整洁一次性重构整个服务端。

服务端线程负责公共入口、身份边界、API 与真实服务接线；Module 线程负责业务语义与接口；UI 线程按契约开发。前端测试替身必须与真实数据源明确区分，交付需要真实 API 联调。Stitch 的视觉稿是界面参考，不是服务端已具备能力的依据。

## 8. 实现顺序与验收

这是一套公共访问能力，不能把“浏览器能打开 healthz”或“证书续期成功”当成整体完成。按以下工作包逐项交付，当前 Config API 作为业务联调基线，不重复开发：

| 顺序 | 工作包 | 首版完成条件 |
| --- | --- | --- |
| 1 | 入口配置与 HTTPS | 一次配置后重启复用；明确实际访问地址；独立公共证书校验、更新与到期状态；支持的托管场景完成申请、续期和失败恢复 |
| 2 | 管理身份、登录与监控权限 | 首次管理员建立、登录、退出、过期、撤销及本机受控恢复；会话在不同节点验证一致；管理、Tenant 与监控权限互不冒用；详细指标受保护 |
| 3 | 最小管理 API | 集群、节点、Volume 的只读查询及证书状态；从任意健康入口访问；部分结果和不可用准确呈现；公开契约不泄漏内部类型 |
| 4 | 内嵌 Web UI | 登录、概览、节点、Volume 页面使用真实 API；Config 按明确 Key 查看与修改；权限拒绝和失败可见；随单个二进制发布 |
| 5 | Go SDK 首版 | Config 已交付操作与必要的认证、错误、期限、取消和安全重试；实际多节点联调；业务凭据不能访问管理接口 |
| 6 | 管理写操作 | 按节点、Volume、Tenant、Repository、备份恢复逐项接入；复用已有预检、受控操作和持久任务；UI 可查询结果与审计信息 |

认证边界和契约确定后，SDK 可先于完整 UI 交付，监控策略随身份工作一起完成；这里表达依赖与验收顺序，不要求全部串行等待。Config 列表在浏览页面需要时补上有界分页，Watch、历史趋势、完整模块控制台、外部身份平台和更多 Gateway 不作为本轮完成条件。首版不需要新造通用 IAM、证书平台或任务调度平台。

按 [开发规范](../development/engine-module-gateway.md) 在 VPS 验证，避免干扰共享长测。至少覆盖：

- 单个 Dubi 服务端即可提供静态 UI，无额外运行时依赖；页面路由、静态缓存和 API 404 正确。
- 未登录、凭据撤销、Tenant 越权、管理身份隔离、内部 RPC 不可访问、浏览器会话保护。
- 任意健康节点的管理查询与业务访问；权限不足、节点失联、部分状态过期均有准确呈现。
- 超时、重复提交、结果不明、并发编辑，以及任务断线后继续查询。
- 探针、指标和完整集群健康语义不混淆；低配置 VPS 上刷新、采集和接口请求受资源预算约束。
- 浏览器、SDK 和监控客户端分别使用正常证书验证访问；证书地址匹配，内部 Node mTLS 不受影响。覆盖证书更新、错误候选、续期失败、重启复用和临近到期状态；使用可控测试时间或测试签发流程验证，不等待真实证书自然过期。
- 登录会话、管理凭据和监控授权在多节点上保持同一安全边界；撤销后不能通过切换节点继续访问。探针不因管理登录或全局共识故障而失去本地存活观测能力。

每个工作包完成后记录代码、使用方法、VPS 验收结果和剩余限制；只有新增证据要求时才扩大测试，不为普通 UI 或 SDK 改动重新启动整套六小时底座长测。未启用公共入口的节点保持原状；启用新 Gateway 后，旧匿名 `/metrics` 采集需配置监控 Token。


## 9. 首版骨架使用与后续接入

一次配置公共入口，之后 `dubi server` 从当前节点元数据目录恢复：

```sh
# 每台节点使用自己的可验证地址；HTTP-01 需要公网端口 80 可达。
dubi server --api-listen 0.0.0.0:7444 --api-host <节点域名或公网IP> --api-acme

# 或者使用部署方管理的证书。
dubi server --api-listen 0.0.0.0:7444 --api-host <访问地址> \
  --api-cert /etc/dubi/https/fullchain.pem --api-key /etc/dubi/https/privkey.pem

# 使用本机已有 Node 身份建立/恢复管理访问，无需额外传入 store/server。
dubi access create --role admin
dubi access create --role monitor
dubi access revoke <credential-id>
dubi gateway status
```

凭据创建结果包含只输出一次的 Token，应保存到私密文件；禁止提交仓库或放入 URL。默认有效期 90 天，可用 `--ttl` 调整，有限有效期最长 366 天；`--ttl 0` 表示永不过期。永久管理员凭据建立的浏览器会话仍最多 12 小时。签发结果不确定时，CLI 显示待处理 credential ID；先撤销该 ID，再重新创建。使用 Node 身份签发管理凭据必须具有既有节点本地管理权限，公共登录接口不能创建管理员。

| 接口 | 首版行为 |
| --- | --- |
| `POST /api/v1/auth/login` | 同源 JSON `{username, password}` 或 `{token}`，二选一；Token 只接受 admin；返回安全 Cookie 和 CSRF Token |
| `GET /api/v1/me` | 返回当前身份；管理员会话可获得 CSRF Token；Tenant Token 返回原 Tenant 身份结构 |
| `POST /api/v1/auth/logout` | 同源会话请求，要求 `X-Dubi-CSRF`；经 Root 确认撤销后清除 Cookie |
| `GET /api/v1/admin/gateway` | 入口版本、当前节点与集群 ID、已接入模块和证书状态；不声称这是完整集群健康 API |
| `/api/v1/config/entry` | 既有业务 API，仍只接受 Tenant Token |
| `/metrics` | monitor/admin 授权；探针仍可匿名 |

登录会话只在 Cookie 使用，不能当作 Bearer Token；Cookie 使用 Secure、HttpOnly、SameSite=Strict 和 `__Host-` 前缀。每节点管理入口限制 32 个并发请求，登录最多每分钟 20 次；每个管理账号或父 Token 最多 32 个未失效会话，下一次凭据创建时清理已撤销/到期会话，活动管理凭据目录最多 4096 条。Root 只保存摘要与权限元数据。登录和退出成功写入不含秘密的进程审计日志；管理账号已接入；完整审计查询尚未提供。

后续管理 API 通过 `GatewayOptions.Admin` 接入统一管理授权及 Cookie 写请求 CSRF 检查，用 `AdminIdentity(ctx)` 获取可信操作者，并在实际写入前完成操作级校验。未来业务 Module 继续通过各自的 Tenant 验证适配器接入；不能因为管理会话有效就读取 Tenant 数据。静态资源、API 404、管理及业务命名空间已分开，Stitch 页面只需替换内嵌页面并按公开契约调用。首批只读管理 API 已按第 11 节接入，契约见 [管理 API v1](../api/management.md)。管理写 API、业务 API 扩展、跨 Tenant 数据授权和 Go SDK 留待后续确定。只读 UI 接入进展见第 13 节。

VPS 验证脚本：`scripts/vps_gateway_acceptance.py --directory <私密演示目录> --host <证书覆盖的地址>`。它针对既有的隔离演示节点，读取目录中凭据，额外创建并撤销一个短期管理 Token；不得直接用于生产环境。单元及模拟 CA 测试同样在 VPS 执行。

## 11. 首批只读管理 API（已批准并实现）

本节设计已获用户批准，九个新增查询与现有 gateway 响应对齐已实现并在 VPS 验证。具体管理写操作、业务 API 扩展和正式 Stitch 页面另行确认。公开字段、查询参数和限制见 [管理 API v1](../api/management.md)。

### 11.1 接口清单

统一前缀 `/api/v1/admin`，本批全部为 GET。任意健康 Gateway 接收请求，路径中的 NodeID 才是目标节点，不能默认操作接收请求的本机。

| 路径 | 主要返回内容 | 首批页面用途 |
| --- | --- | --- |
| `/cluster` | ClusterID、运维观测状态、问题原因、节点数量、区域摘要、已观测容量和维护摘要 | 集群概览 |
| `/regions` | RegionID、运维观测状态及原因、登记节点数与各状态数量、已观测容量、维护摘要和观测覆盖情况 | 区域列表 |
| `/regions/{region_id}/nodes` | 指定区域的节点列表，字段与 `/nodes` 一致 | 区域内节点列表 |
| `/nodes` | NodeID、可为空的名称、Region、成员状态、观测健康、容量/维护摘要、观测时间 | 节点列表 |
| `/nodes/{node_id}` | 单节点登记信息、观测状态、Volume/维护摘要、支持的数据项 | 节点详情 |
| `/nodes/{node_id}/volumes` | VolumeID、路径、登记状态、健康、写隔离、文件系统容量及观测时间 | Volume 列表 |
| `/nodes/{node_id}/volumes/{volume_id}` | 单 Volume 状态、容量与相关迁移/故障信息 | Volume 详情 |
| `/maintenance` | 按节点列出实际观测到的修复、平衡、跨区域补齐和卷迁移情况 | 全局维护进展 |
| `/nodes/{node_id}/maintenance` | 指定节点的维护状态、阶段、已处理数量、最后进展、错误及统计缺失情况 | 节点维护详情 |
| `/gateway` | 保留现有入口信息、节点/集群标识、已接入模块和证书状态；按本节统一管理响应结构 | 当前入口信息 |

首批提供独立区域列表和区域内节点列表，支持页面从集群进入区域、再进入节点。RegionID 使用现有 Runtime 区域标识，不增加另一套区域身份或创建流程。区域列表基于集群已确认的区域/成员目录，不能仅从成功响应的节点推导；区域节点全部失联时仍保留该区域并明确观测缺失。`/regions/{region_id}/nodes` 与 `/nodes?region=...` 复用同一查询与节点返回结构，支持相同的名称、状态筛选及分页；嵌套路径不再接受重复的 region 参数。区域列表按 RegionID 稳定排序，支持状态筛选及统一分页；所有区域状态与容量遵守下文的观测时效和覆盖范围约定。已确认不存在的区域返回 404；不能确认目录时返回 503，不能将区域失联当成不存在。`maintenance` 只是现有后台能力的只读观察，不建立维护任务资源或第二套任务状态机。不存在的进度或不支持的能力不能为了页面效果编造。

NodeID/VolumeID 是稳定的 API 标识，页面优先展示节点名称。节点名称可为空、可更改，不作为状态更新的永久主键。节点列表支持 `region`、精确 `name`、观测 `status` 筛选；维护列表支持 `node_id`、`region` 和维护 `kind` 筛选。列表采用 `limit`（默认 50，最大 200）和不透明 `cursor`，未知参数返回参数错误；游标须绑定筛选条件。节点目录按 NodeID 稳定排序，分页不承诺跨多次请求的原子快照，成员变更后刷新第一页重新获取。

### 11.2 响应与观测语义

新管理查询统一为 `data` 与 `meta`；列表的 data 包含 `items` 和 `next_cursor`。现有 `/admin/gateway` 随本批调整，同时更新接线页；登录、身份接口和 Config 业务契约不在此次包装调整范围。

`meta` 至少包含请求关联 ID、响应生成时间、`complete` 和有界 `errors` 列表。每份节点/Volume/维护观察独立提供 `observed_unix` 和 `stale`，不能用响应生成时间冒充数据采集时间。`complete` 表示请求范围的数据是否齐全，`stale` 表示具体观察是否过期；两者不能代替健康状态。缓存刷新失败时允许返回明确标记的最近观察，缺失项为 null/unknown，不能填零或当成空列表。

运维观测状态使用 healthy、degraded、unavailable、unknown，且返回稳定原因码与可读说明。节点探测超时仅代表该次观察无法到达目标，不表示节点已被删除、永久损坏或需要自动改变成员。集群状态是有范围和时效的运维结论，不是所有 Module 可读写或所有数据已达到多数持有的证明；修复队列为空也不能作为这种证明。

容量字段明确分开：

- `filesystem_total_bytes` / `filesystem_available_bytes`：所在文件系统容量与当前可用空间，不能命名为 Dubi 业务数据用量；同节点共享文件系统的多个 Volume 需要去重后汇总。
- `writable_bytes`：现有空间保护策略下观测到的可写额度，属于动态观察，不是已预留空间或对某次写入的保证。
- 集群总览只能汇总已观测节点并展示覆盖数量；跨节点共享文件系统无法可靠识别时，不能声称已完成全局物理容量去重。逻辑业务数据容量、物理冗余开销或精确 Pack 占用没有可靠来源时不提供。

维护详情返回当前阶段、已处理数量及其单位、最后进展时间、错误、未完成补齐数量和是否缺少完整扫描观察。没有可靠总量时 total 为 null，不输出完成百分比或预计剩余时间。自动平衡没有独立进度来源时返回未提供，不为 UI 合成任务 ID 或伪造 idle 状态。初版保留诊断扩展位置，但普通概览不要求用户理解 RaftID、Group、Keyspace 或 Range。

### 11.3 权限、失败和开销

- 首版使用既有 admin Token / 管理员会话；monitor 和 Tenant Token 不得访问上述管理 API。管理权限仍不授予 Tenant 内容读取权限。本轮不增加角色编辑器或任意 RBAC 配置。
- 401：凭据无效或会话已过期；403：身份有效但没有管理权限；404：已确认资源不在成员/Volume 目录中。已对管理路径区分无效凭据与有效但无管理权限的 Tenant/monitor 身份。
- 聚合查询部分节点失败：返回 200、`complete=false`，明确失败节点和缺失数据。单节点详情可在确认登记后返回其目录信息与 unavailable/unknown 观察；无法获得其 Volume/维护详情且无可用缓存时返回 503。
- 无法确认身份权限时返回 503，不能为了显示降级页面绕过授权或先返回缓存。不存在与不可达必须分开；503 与 404 不可互换。HTTP 状态表示查询结果，不代替集群健康状态。
- 复用 Runtime 受控状态与内部查询，抽取公共管理查询服务供 CLI/HTTP 复用，不执行 CLI 或解析终端 JSON。现有 CLI 汇总逻辑仍在 command 包，不能把它误称为已可直接复用的服务接口。
- 同一入口的汇总查询复用短期缓存、合并同时发生的采集，限制并发、范围和总时限；不让一个页面的多张卡片分别扫描全群。首版页面刷新建议 10 秒，后台标签页退避。授权仍按现有 Root 确认策略执行，缓存不能延长已撤销凭据的授权。
- CPU 占用率、RSS、版本、运行时长等数据只有在目标节点有可信来源时提供；缺少远端查询字段则明确补采集适配，不能直接拿 Gateway 本机的数据代表远端节点。首批不为趋势图增加历史时序存储。

## 管理账号、个人资料与密码

账号是集群管理身份，独立于 Tenant 和 API/SDK Token；首次创建必须经已有管理员授权，不开放匿名注册或无认证的“首个账号抢占”。账号存于 Root，通过 Raft 和集群备份/恢复保存，任意节点均可登录。最多 256 个账号，当前所有账号均为集群管理员，不隐式授予 Tenant 业务数据权限。

- 账号标识：新建账号使用 `account_` 加 12 位小写十六进制值；既有 `acct_` 标识仅兼容读取及原有引用，不再生成。
- 账号：3–64 位字母、数字、点、下划线或连字符，统一小写且集群唯一；创建后不可修改。
- 显示名称：1–128 UTF-8 字节；个人资料仅修改这个字段。顶部使用当前账号名称，重新读取身份时同步改名。
- 密码：至少 12 个 Unicode 字符、最多 256 字节，不修剪空格。保存随机 16 字节盐和 Argon2id 哈希（v19，64 MiB，3 次，1 lane，32 字节输出），不保存明文或可解密密码。算法参考 [RFC 9106](https://www.rfc-editor.org/rfc/rfc9106.html)。单进程最多一个密码哈希计算同时执行，限制并发计算的内存压力。
- 账号密码登录与 Token 登录共享每节点每分钟 20 次登录限制；账号管理中的密码操作也限每分钟 20 次。不存在账号、错误密码和已禁用账号返回相同登录失败消息。
- 修改显示名称不影响会话。修改/重置密码、禁用或重新启用账号会更新认证版本并清理已有账号会话；登录与改密并发时，Root 拒绝旧版本的新会话。禁止禁用或删除最后一个启用的管理账号。删除账号在同一 Root 提交中清除其会话、账号记录和用户名索引；用户名可以用于新账号，但不会恢复旧身份或旧会话。
- 账号会话最长 12 小时，使用安全 Cookie、CSRF 和每次访问的 Root 权限确认；密码或 Token 不存入浏览器持久存储。Token 登录保留给初始化及恢复操作；API/SDK 继续使用各自的 Token。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/admin/accounts?q=&limit=&cursor=` | 启用账号在前，各状态内按不可变创建顺序倒序，返回 items、total、next_cursor；排序与分页游标一致，不含密码、盐或哈希 |
| `POST /api/v1/admin/accounts` | request_id、username、name、password 创建账号 |
| `GET /api/v1/admin/accounts/{id}` | 脱敏账号详情及 revision，不存在返回 404 |
| `DELETE /api/v1/admin/accounts/{id}` | request_id、revision；删除账号及其会话，禁止删除当前登录账号或最后一个启用管理员 |
| `PATCH /api/v1/admin/accounts/{id}` | request_id、revision，按需提交 name、disabled、password；管理员重置无需旧密码 |
| `GET /api/v1/admin/profile` | 当前账号的个人资料和 revision |
| `PATCH /api/v1/admin/profile` | request_id、revision、name；只改自己的显示名称 |
| `POST /api/v1/admin/password` | request_id、revision、current_password、password；校验当前密码后修改，成功后重新登录 |

这些接口位于现有 admin 授权层；客户端不能修改角色、密码哈希、认证版本或创建索引。Token 登录没有个人资料或个人密码，右上角入口指引进入管理账号页面。`/api/v1/me` 和账号登录响应增加 account_id、username、name。浏览器改名成功后立即更新右上角，改密成功后回到登录页。

写操作使用 revision 防止并发覆盖。网络中断或结果未知时，先刷新资料/列表或尝试新密码登录核对；密码操作重新计算随机盐，因此不自动重放同一请求 ID，页面在结果未知时阻止重复提交。消息和通知阅读状态独立于账号，为集群共享。

账号列表复用凭证页的卡片标题、搜索栏、紧凑表格和分页样式，状态放在操作左侧，“详情”放在最右。详情抽屉支持编辑及删除，删除前确认。删除使用固定请求标识和读取到的 revision；版本冲突返回 409，结果未知时可重试同一删除请求，不存在的账号删除视为成功。状态变更后刷新第一页，分页不承诺跨请求原子快照。


### 引擎与模块注册目录

`GET /api/v1/admin/components` 返回标准 `data/meta` 管理响应，需要管理员身份。

- `data.node_id` 为当前响应入口节点，`scope` 固定为 `entry_node`。这份目录描述实际服务装配结果，不是跨节点健康或性能汇总。

- 大小限制来自 State 实际常量；没有持久化配置接口的项目不提供编辑。端点只支持 GET，不接受查询参数。
- 管理目录读取不额外执行跨区统计，不修改租户或业务数据。尚未接入的规划模块不出现在真实目录中。
