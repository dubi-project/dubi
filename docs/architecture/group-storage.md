# Group 创建与 Raft 存储恢复边界

本阶段补齐本地创建栅栏：空目录不再等价于一个新 Group，`lastIndex == 0` 也不再足以决定 bootstrap。适用于 Root 和普通数据 Group，不引入任何用户配置。[自动区域 Group](region-cohorts.md)现已把 Root 初始计划与各节点建组权限接通；本实现提供其本地持久前提。代际 fence 的全员应用证明和数据耐久回执仍需实现。

## 三层关联

1. Store 的 `DUBI_RAFT_GROUPS` 登记 Group 资源身份与生命周期，独立于 `<store>/dubi-raft-groups/<group>`。Group 目录中的 `GROUP_IDENTITY` 必须与其对应。整个 Group 或父目录丢失时拒绝重建；登记文件丢失但资源仍在时拒绝收养。
2. Group 目录中的 `DUBI_RAFT_STORAGE` 登记日志资源，`dubi-raft` Pebble 内同步保存同一个日志身份。Store 的 Group 登记再绑定该日志身份。因此日志目录及其旁边的登记文件一起丢失，也不能当成第一次创建；换成另一份或空数据库同样拒绝。
3. 日志中在第一份 Raft Ready 之前保存 GroupID、本地 RaftID、初始加入模式和 bootstrap 成员集合。后续调用不能换 Group/本地身份/初始成员，learner 不能改成 bootstrap。原始 bootstrap 意图已保存而日志尚未开始时，恢复可读取原集合，无需重新填写 peer。成员扩缩仍通过正常 Raft ConfChange，不修改初始意图。

这些都是自动生成、内部使用的记录，不是新的运维 ID、目录配置或副本数设置。Pack 布局不变，多个 Capability/Tenant 继续共用卷内 Pack。

## 初始化、同步与失败处理

Group 目录和日志各自采用 pending → active 发布。pending 保存新建目录的 device/inode，恢复不能改用同路径的新目录；active 使用持久身份，不依赖跨重启的 inode。记录写入采用临时文件同步，再发布并同步父目录。对之前发布结果不确定、但重试能读到的记录，仍重新同步目录后才继续。

日志内身份同步后才能发布 active；活动库打开前先用 Pebble 只读检查确认已有数据库，再用 `ErrorIfNotExists` 打开并核对内部身份。测试发现单用 `ErrorIfNotExists` 仍会在空替代目录中创建 LOCK，现已增加前置只读检查。

第一份日志或快照与 started 标志同批同步提交；已经开始的 Group 不允许以零日志重新 bootstrap。Group 开始处理 Ready 前，日志身份已绑定到外层 Store 登记。发生错误时关闭已接管的状态机、数据库及登记租约，不发布可用 Group。

Group 登记内部限制 4096 条、2 MiB，文件读取有界；该限制不是已验证的部署规模。目录登记的短发布阶段串行化，数据库恢复、状态回放和快照安装不占 Host 路由锁。文件系统调用本身不能被上下文强制中断，尚不能宣称全局 IO 隔离或延迟上限。

## 格式和操作边界

- Group 身份标记现在为 v2，包含随机资源身份。没有新登记或缺少 formation 的旧开发数据不会自动收养、改写或迁移。尚无已验证的滚动升级/旧格式迁移通道；不要直接覆盖已有重要数据目录运行新版本。
- 保留错误现场。不要删除登记、日志或手工生成 ID 来让启动通过。现阶段没有自动灾难恢复命令；后续恢复须按新身份与集群确认协议实施。
- 状态机索引的正常快照/日志回放重建仍保留，不能把可重建索引与唯一的 Raft 持久历史混为一谈。
- 这还不是覆盖全部 Pack、状态库、临时目录的统一 Node/Store 资源清单，也没有 Checkpoint 一致切点、备份保留或 GC pin。整份 Store/全部权威登记一起丢失、回滚到旧备份、主动篡改或所有路径竞争，不由本记录自动修复或完整防御。
- 标记访问使用目录句柄和物理文件检查，但 Pebble 仍通过路径打开与操作数据库；尚未建立完整 descriptor-backed VFS，不声称对特权进程运行期替换整个目录树具有完整隔离。

## 本地证据

测试覆盖 Group/父目录缺失、空目录和 symlink 替代、登记/owner 损坏或丢失、外来资源身份、并行创建不丢记录、pending 目录替换、数据库内身份缺失、初始成员与 learner 模式不可改变，以及已经开始但丢失日志的拒绝。

子进程直接退出覆盖 Group 登记五个阶段、日志登记五个阶段，以及实际 OpenGroup 的日志打开、外层绑定、formation、初始 Ready 四个阶段。恢复后可提交并重开读取，Root/普通 Group 的日志与状态同时缺失、日志连同登记缺失、整个 Group 缺失均拒绝重新 bootstrap。测试只移动临时目录中的文件保留现场，不操作用户 Store。

这些是同机临时存储、进程退出及竞态测试，不是独立磁盘/真实掉电/WAN 资格。自动初始区域 Group 的集成验证及尚缺能力单独记录于区域集合文档。

首轮完整门禁还捕获了已有双节点证书续期测试的超时：该用例设置 1 ms Raft tick 和 10 ms 成员调度，实际日志出现加入期间选举反复切换，之后报告读屏障超时。现改用正式默认时序验证续期，不放宽原超时、不忽略错误；针对该用例连续十轮竞态测试通过。生产 Raft 参数及续期重试策略未因该测试更改。
