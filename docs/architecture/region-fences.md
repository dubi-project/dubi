# 区域代际栅栏：数据 Group 持久原语

这是[区域集合](region-cohorts.md)从“已建组”走向可验证应用确认的下一层，不是业务数据回执。通用数据 Group 已支持 `region_fence` 命令、本地一致观察、认证远端观察和两种快照恢复；正式托管运行时已接入**第一代初始建组的自动提案、全员观察与 Root 确认**，以及独立的[严格增长交接](region-handoff.md)。业务数据多数回执尚未实现。

## 绑定内容

栅栏绑定 Region、Group、cohort generation、Root 计划位置、Root Group descriptor epoch，以及排序后的完整 voter/learner 集合。另绑定该数据 Group 最近一次应用成员变更的位置 `MembershipIndex`。Root index 与数据 Group index 属于不同日志，不能直接比较。

栅栏不含 Tenant、Capability、业务 payload 或物理 Pack 位置。底层状态机处理它，不调用任何模块 Handler；编码器拒绝将它与 Range 激活或业务 mutation 混入同一命令。内部记录最多 4096 个成员，至少三个 voter；不足三成员的小 Region 则要求全部成员为 voter。元数据读取上限 1 MiB；这些是有界处理限制，不是已验证的生产规模或用户参数。单节点栅栏只证明该 Region Group 的控制面边界，不赋予本地 `LocalReady` 语义；小 Region 的写入仍必须走跨 Region 同步多数。

## 原子应用与失效

- 每次 `ApplyMembership` 将 ConfState、成员变更位置和 applied index 同步写入同一批次。
- 应用栅栏时，在同一状态机锁内检查目标 Group、当前稳定 ConfState 的全部成员/角色及精确成员位置。过期、joint 或不匹配的命令持久拒绝，不把业务错误当成磁盘错误。
- 成功栅栏、请求摘要/结果和 applied index 同步提交。相同请求 ID 的重放保留第一次结果和原始栅栏位置；同 ID 不同内容在结果读取时明确冲突。新 ID 不能无条件覆盖同一栅栏。
- 后续成员变更使旧栅栏失效，哪怕成员名单又变回原样。判断同时依赖成员位置，不靠名单相等来复活旧权限。
- 同一 cohort 重新栅栏需要同一 Root 计划和 Node 集合、更高的 descriptor epoch，成员变更位置不能回退。Root 完成无实际成员变化的任务时允许位置不变、只刷新 epoch；发生过实际成员变更则必须匹配新的位置。下一代还必须是紧邻代际、计划及成员位置前进和严格增加 Node；learner 同样计入参与集合，不允许替换、缩小或跳代。v5 进一步要求先[持久封口](region-handoff.md)，候选必须绑定该交接且成员位置在封口后；候选不是写入激活。已激活交接不得用普通 refence 任意覆盖。
- 只保留最新的本地栅栏记录；旧命令结果保留，Root 的 cohort 历史另行持久维护。这里不是完整历史证明归档或 GC 协议。

`RegionFence()` 返回同一把读锁下的本地状态、当前成员位置、ConfState 和 `Active`。调用方仍需真实 Group ReadIndex；`Active` 仅说明该本地切点中栅栏尚未被成员变更淘汰，不证明其他节点磁盘、不授予公开写权限，也不代表 LocalReady/GeoReady。同步结果不确定时整个状态拒绝服务，重开后按实际持久结果恢复。

状态机不能在确定性 Apply 中读取另一个 Root Group 的当前状态。因此 Root 计划的实时授权、epoch/成员任务竞态、全员应用检查和最后 Root CAS 由[初始确认协调器](region-cohorts.md)及[增长协调器](region-handoff.md)各自负责；不能把请求里的 Root index 当成可信远端证明。该协议不提供跨 Group 原子事务，后续写入仍需当前代际授权和数据证明。v5 已在本地 Apply 阻止失效区域 fence 或未激活交接期间的业务 mutation；空 Range 的控制面初始化不解除该写入门禁。这不是数据多数回执或公开授权。认证远端查询原语按下述边界接入正式 Node，并包含同切点交接记录。

## 认证远端观察

内部 `RegionFenceService.Observe` 直接请求指定节点，不跟随 leader 重定向：需要的是这个参与者自己的持久应用状态，不是可互换的读取位置。它不是用户/Tenant API，不暴露业务数据，不修改 Root 或数据 Group。

服务端先验证 Node mTLS 与请求的 Cluster/发送方/目标，再通过 Root ReadIndex 在同一 Root 成员切点确认调用者和本节点资格，并核对数据 Group 已登记。对目标 Group 完成 ReadIndex 后读取本地一致切点；返回前再次确认 Root 成员与当前 TLS 授权。历史节点登记不能代替当前成员资格，Root learner 仍是合法调用者。检查是有时间点边界的授权，不是原子全局吊销或跨 Group 事务。

响应绑定 Cluster、Group 和被观察 RaftID，包含 Root/Group 各自的读屏障位置、数据应用位置、成员变更位置、ConfState 与可选最新栅栏。客户端独立验证身份、大小、读屏障已应用、稳定成员且包含目标节点、栅栏归属/位置关系及 Active 的一致性；不把服务端布尔值当作无需核对的证明。没有栅栏可返回 Found=false；成员变化后的旧栅栏可返回 Active=false；joint、少于三个 voter 或目标已不在数据 Group 中不返回可接受观察。

v5 响应另带状态格式和可选交接记录。客户端拒绝旧/缺失格式、错误交接关联、位置超界，以及下一代 fence 缺少交接；`Active` 仍只指成员配置匹配，不意味着交接已激活。服务端最多 8 个活动观察请求，不排队；客户端和服务端均设 10 秒内部上下文。请求最大 4 KiB，栅栏和交接各最大 1 MiB，ConfState 最大 256 KiB，总响应最大 2 MiB + 256 KiB + 4 KiB。所有失败、取消和超时归还槽，不启动可累积的后台等待 goroutine。该限制发生在 protobuf 解码后，不是总连接/握手/进程内存预算，也不能强制中断任意磁盘操作。

调用方还必须用 Root 的当前计划、代际、descriptor epoch 和成员任务状态核对每份观察；初始确认与增长候选发布要求新集合全员验证，增长的旧封口授权要求固定旧集合的严格多数精确观察，然后完成 Root CAS。单份合法观察不验证栅栏里的 Root 计划当前仍获授权，也不能直接触发 cohort 确认或 LocalReady/GeoReady。旧节点没有该 RPC 时不计入旧多数，也不能在新候选阶段冒充“已确认”；版本协商与滚动升级仍未完成。

## 快照与版本

文件和内联快照都携带最新栅栏与成员变更位置，恢复前验证 Group、位置上界、栅栏与结果摘要/位置的一致性、成员位置先后关系，以及仍有效栅栏与该快照 ConfState 的精确匹配。文件生成使用捕获时的固定视图和 ConfState；生成期间发生新成员变更不会污染旧切点。错误镜像在清空目标状态或写 Pack 之前拒绝。

Capability 状态与快照当前使用 **v7**，新空库标记 `meta/format=7`，文件头 `capstate-v7`。v4 引入成员位置栅栏，v5 增加持久代际交接与写入门禁，v6 增加[不可变记录权威引用](immutable-records.md)，v7 增加绑定引用发布位置与 Region fence 的本地多数确认记录；旧 v6 及更早开发格式明确拒绝，不做收养、重写或隐式迁移。观察响应的状态格式也必须匹配当前版本。重要旧数据不能直接覆盖运行新版。Root、Pack 及本地 Pack 引用格式不变，混合 Tenant/Capability Pack 布局不变。版本协商、滚动升级和迁移通道仍未完成。

## 本地验证

测试覆盖严格命令信封、成员/角色/代际边界、learner 增长、同请求重放、请求内容冲突、成员 ABA 后失效、两种不确定同步结局、重启、活动与失效栅栏的文件/内联恢复、捕获后成员变化，以及带有效文件摘要但语义损坏的镜像拒绝。

正式 CLI/TCP/mTLS 三/九节点测试由后台协调器自动提交真实栅栏并确认 Root，测试不再代替运行时提案；逐节点 ReadIndex 后检查本地应用，并从另一个存活节点通过认证 RPC 核对相同记录；随后验证节点停机、领导权变化和整群冷启动保持原 fence。RPC 专项覆盖移除节点复用 TLS 连接、等待后成员移除/授权失效、目标/集群/Group 响应错配、损坏/超限/未应用响应、过载、超时、取消与槽归还。这是同机初始确认协议验证，不是业务数据回执、独立磁盘/WAN/掉电资格或生产批准。
