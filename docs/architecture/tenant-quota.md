# Tenant 逻辑存储软配额

## 目标和边界

租户配额采用本地准入、后台汇总的软限额。多个入口同时写入时允许短暂超额；各节点收到用量更新后，新的增长写入会被拒绝。配额不是全局严格容量预留，不为每次业务写入增加跨节点查询或 Root 共识。

配额服务由每个节点的 Runtime 统一持有，所有 Engine binding 共享本节点的租户用量缓存与待同步增长估计。Engine 不装配配额服务、不调用准入或结算方法，只描述逻辑键更新后的大小和业务操作结果；Module 无需参与。当前 State / Config 按 `key 字节数 + value 字节数` 计量，删除计为 0。冗余副本、Pack 文件和内部元数据不重复计入业务用量。不同 Module / Engine 的用量按 Tenant 合计。

## 写入路径

1. Engine 调用统一的 `Bound.Mutate`，提供 `LogicalValue`（逻辑键、更新后大小）、写入内容及普通业务读取适配器。适配器解释请求身份、回执及 CAS 结果，并透传当前引用中的 Runtime 用量元数据；不做配额判断。Runtime 复用这次读取取得旧大小和操作结果，不新增配额专用网络读取。
2. Runtime 从内存缓存读取租户限额和已同步用量，叠加本节点尚未同步的增长估计。缓存首次使用只加载本地 Root 副本，无网络屏障。
3. 已知不足时拒绝增长；删除、等量修改和缩小仍允许。相同请求不重复占用本地增长估计。权限认证、Owner 路由和数据多数确认保留原有语义。
4. Owner 的 Engine Handler 通过 `Transaction.PublishRecord` 提交数据引用和逻辑大小，由 Runtime 在同一事务中保存发布位置和有序待同步索引；CAS 拒绝和历史请求重放不产生新增计量。
5. 正常写入完成后立即返回，不等待 Root 账本更新。Runtime 根据数据发布位置和业务回执处理本地增长估计；已同步报告覆盖该发布位置后释放估计，持久业务冲突可立即释放。结果不明不能仅凭超时当作未写入。已发布但尚未确认的重试可以继续数据确认，不再次占用额度；历史成功或失败回执直接返回。

已开启计量的租户必须使用逻辑写入入口。旧的 `Bound.Write` / `Service.Write` / `WriteLocal` 原始写入入口拒绝这类租户，防止新增 Engine 忘记提供大小而静默漏计。内部物理复制、Repair、Rebalance 和已准入写入的转发不再次计量。异步维护属于节点生命周期，即使没有启动 HTTP Gateway 也运行，不依赖 Config Module 装配。

## 后台同步

每个 Owner Group 的 Leader 按提交顺序读取本地计量索引，低流量时每 5 秒合并一批、每批最多 64 项；满批时立即继续排空后续批次，通过一次 Root 命令汇总。索引只保留各逻辑键的最新版本，覆盖会将条目移到末尾，因此无需每轮扫描全部业务键或读取 Pack 内容。

报告传递当前绝对大小及 Range / Owner / Epoch / Index，不直接发送不可去重的加减数。Root 用本次大小替换上次大小并调整租户总量，重复、乱序、迟到旧 Owner 报告不能重复计费或回退用量。删除的零值报告继续保留，保证离线、重启或丢失 ACK 后仍能释放额度。

只有 Root 确认批次后才推进后台游标。重启或 Leader 切换会重放索引，Root 去重；计量记录与数据发布同一事务落盘，并随 Raft Snapshot、Cluster Backup/Restore 保存。没有独立 Node Snapshot、外部计量服务或用户维护配置。

每个入口另有独立维护循环，每秒从本地 Root 副本更新已使用租户的内存缓存，不受网络报告阻塞。读取元数据在准入锁外执行，仅用极短临界区替换缓存，避免后台读盘拖慢内存检查。单租户本节点未结算增长请求有数量上限，维护循环停止超过 30 秒时拒绝新增增长；不会因为释放未知结果而持续放大额度。

## 语义和限制

- 软配额允许同步窗口内的超额，不能承诺全局严格不超限或固定超额百分比。超额量取决于并发入口、在途数据和同步延迟。
- 用量异步更新；管理界面显示已汇总的用量，不是每个节点此刻的精确总和。
- 配额检查不再执行同步 Root 预留、结算或逐笔准入确认。业务认证和原有数据路径仍可能跨区，不能把全部业务延迟归因于配额。
- 不限额租户仍计量，便于以后设置限额。未计量的早期开发测试租户仍显示不可用，不引入历史数据自动迁移。
- 旧严格预留命令只保留已有 Raft 日志、快照的解码/重放兼容；新业务路径不生成票据。已有完成计量的键可被新绝对大小报告接续，不搬运业务数据。
- 修改引用格式后，验收集群所有节点需要统一升级，不能让旧节点长期参与解析新引用。
