# 普通读取与节点发现入口验证（2026-11-05）

本轮接续[内存与首次 Range 验证](memory-range-latency-verification.md)，处理普通读取重复 Root 往返，以及六个并发 CLI 请求中两个被发现接口限流的问题。实际测试和探测在 VPS 执行，开发机只做交叉编译和静态检查。

## 改动和边界

1. **区分节点发现与入群准入。** CLI `connectDataNode` 在数据请求前调用 DiscoverRoot，核对协议、成员和服务端身份。原 DiscoverRoot 与 JoinRoot 共用四个槽，六并发在数据请求发出之前就可能被拒绝。现在 JoinRoot 独立四个槽，DiscoverRoot 独立八个槽，与当前数据入口八槽规模一致。继续立即拒绝超额请求、附重试建议，不增加队列。认证、证书到期、成员/Fence、协议与消息限制保持不变。服务端非 voter 的 Root ReadIndex 使用 Group RPC，不经过 DiscoverRoot；上一轮对此调用链的推测已修正。
2. **合并同一次读取中的重复 Root 复核。** Reader 已先读取并校验不可变字节，再观察实际物理多数；物理观察后的 Owner 引用检查保留，将其后重复的 Root 检查统一放到 `CheckReadCurrent`。后者先核对精确引用、确认记录及 Owner Fence，再取得新鲜 Root 切点核对 Region 计划。最终检查成功前绝不返回数据。正常已带准入切点的读减少一次 Root 往返；未带切点仍自行获得初始切点。
3. **保留写入语义。** 导出的完整观察、写入耐久重试不使用延后路径。遇到旧代际确认而需要刷新时，重新执行完整观察后才允许进入原刷新逻辑；暂存的物理观察不授权写操作。没有跨请求证明缓存，没有减少物理多数或调整成员分母。

## VPS 测试

在 TT02 独立测试进程运行 `recordwrite`、`rootjoinrpc` 两个完整包的测试，全部通过，包括：

- 普通读覆盖写、确认记录替换、区域改变、最终 Root 不可用和取消时不返回字节。
- 无准入切点自行读取 Root；旧确认的暂存观察不能绕过 Root 不可用直接触发刷新。
- 原缺失副本补齐、失去多数、权限拒绝、确认刷新、写入耐久及修复用例。
- 发现槽耗尽时入群仍有独立槽；入群槽耗尽时发现仍可用；发现过载带重试建议、取消归还槽。
- 现有证书、成员、协议视图和 Fuzz 种子用例。
