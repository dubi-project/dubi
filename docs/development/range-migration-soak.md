# 数据寻址迁移：六小时稳定性长测

本轮固定服务二进制 SHA-256 为 `65942584106c6b78693f643e7047a22a823990744adc040324cf79ca7e119f7f`，使用重建后的 SG/FF/TT 三地区九节点。功能与格式迁移的前置结果见[迁移验证记录](module-addressing-verification.md)。本轮不是旧版六小时成绩的延续，也不替代故障演练、全新集群备份恢复或生产资格验收。

## 覆盖与判定

- 从 VPS 发起六小时低速流量，约每 30 秒一个循环，九个节点轮流作为写入口，三地区轮流读取并校验完整内容；正常流量交替使用三个区域拥有的 Range。
- 每 15 分钟创建三个新 Tenant，在三个 Region 分别触发首次写入自动建 Range。各 Tenant 使用相同 Key、相同调用方 RequestID、不同值，验证独立 Range 与区域 Owner；随后通过另一个区域的入口重试，要求返回原 applied index。
- 新 Range 的专用记录写入后先不做逻辑读。满三分钟后通过只读持有接口观察九个节点，要求至少两个 Region 各有至少两个实际持有节点，且 StoreID/VolumeID 属于本轮身份；物理检查通过后才读回，避免把读取拉取当作后台复制成功。
- 同时读取历史记录；每分钟检查拓扑、Root quorum、节点/卷健康与 Repair/Geo 待办。允许暂停新写入等待正常 Geo 队列最多 180 秒，所有中间状态保留；其他故障直接失败。
- 任一请求失败、超时、值不一致、幂等结果变化或物理多数不足，立即结束本轮流量并保存响应及本机日志。不会重试请求后将失败改记为通过。
- 九台各有独立的只读采样进程，每 30 秒记录服务 PID、运行中二进制摘要、RSS、系统可用内存、I/O、负载与 systemd 内存数据。版本、身份变化或意外重启会使对应采样失败，最终验收必须合并检查全部九份记录。
- Module 身份仍由服务端固定绑定。本轮使用内部 Record 探针验证 Tenant 隔离，不通过客户端伪造 Module 身份；不同 Module 之间的隔离沿用独立专项测试，不能用本轮结果冒充多业务模块验收。

## 工具与运行方式

- `scripts/vps_range_soak.py`：独占本机验收锁，保存每次调用的参数、原始响应、耗时及进度；已有输出目录拒绝复用。正式任务为 21600 秒，随后排空最后物理检查并要求健康状态收敛。
- `scripts/vps_resource_watch.py`：只读节点进程和 `/proc`，持续 21900 秒以覆盖六小时流量及收尾。它不改服务、不注入故障，也没有节点间 SSH。
- 两者都使用有限时长的 systemd 临时服务，不是定时任务。VPS 独立运行，开发机断开或对话结束不会停止测试。正式运行期间冻结服务版本和成员拓扑。
- `vps_cluster_tools.py` 已识别新的流量进程，现有部署/故障工具会把它视为活跃验收负载。

启动前完成 65 项 VPS 工具回归；一次缺少配套 Bash 夹具的工具测试失败保留在 `tool-tests-first.log`，补齐后完整通过。首次短验证因 systemd 环境缺少交互 CLI 地址上下文，误连默认 7443 端口；日志保留于 `smoke/`。脚本已改为明确使用经过验收的入口地址，再执行 `smoke2/`，不改 DUBI 服务或用户 CLI 默认行为。
